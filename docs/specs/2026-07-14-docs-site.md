# Docs site: versioned GitHub Pages documentation

## Goal

Publish browsable documentation for libcivicclerk so users can evaluate and
use the library without reading source. The site renders the existing
docstrings (google-style + attribute docstrings) as an API reference,
carries a prose usage guide, and is versioned per release with a version
selector, deployed to GitHub Pages on tagged releases.

## Requirements

- A local one-command build produces the full site with zero warnings.
- The API reference is generated from docstrings (mkdocstrings/griffe) —
  every public class, method, attribute description, and error appears
  without hand-duplicating any of it.
- Landing page reuses README content (single source of truth — no copy).
- A usage guide covers what the README only summarizes: datetime
  semantics, polite pacing and how to disable/extend it (careful/injected
  clients), download gotchas (no resume, empty-200s), error taxonomy,
  pagination behavior.
- docs/decisions.md is published as an "Architecture decisions" page;
  docs/specs/ is excluded from the built site.
- Pushing a `v*` tag deploys that version to GitHub Pages with mike; the
  site shows a version selector; `latest` alias points at the newest
  release.
- CI builds the site (no deploy) on pushes/PRs so docs breakage fails
  before a release tag.

## Out of scope

- No PyPI publish workflow (tags trigger docs only, for now).
- No changes to library code or its docstrings beyond what a strict build
  surfaces as broken cross-references.
- No custom theming beyond mkdocs-material defaults and palette basics.
- No analytics, search plugins beyond material's built-in, or comment
  systems.

## Constraints

- Docs tooling lives in a `docs` dependency group; runtime deps stay
  httpx-only. Build via uv (`uv run --group docs ...`).
- mkdocs-material + mkdocstrings[python]; versioning via mike
  (mkdocs-material's native version-selector provider). Pages serves the
  `gh-pages` branch that mike maintains.
- `docs/` stays the mkdocs source dir; use mkdocs `exclude_docs` for
  `specs/`. README reuse via a snippet include rather than duplication
  (pymdown snippets can include files outside docs_dir).
- Site URL: https://chapinb.github.io/libcivicclerk/ — set `site_url` so
  sitemap/canonical links are right.
- Public-repo constraint applies to all docs prose: no references to any
  specific municipality; examples use fictional tenants.
- Docstring cross-reference style (`:class:`/`:meth:` roles) is Sphinx
  reST syntax; verify mkdocstrings renders or configure/normalize — the
  strict build decides.

## Environment

- `uv sync` — install dev tools; `uv sync --group docs` adds docs tools.
- `uv run --group docs mkdocs build --strict` — the build gate.
- `uv run --group docs mkdocs serve` — local preview.
- `uv run pytest` / `prek run --all-files` — unchanged library gates.

## Decision log

- 2026-07-14: Deploy on tagged releases (not every push) with per-version
  docs and a selector, per maintainer decision; mike chosen because it is
  mkdocs-material's supported versioning provider.
- 2026-07-14: README stays the complete quickstart; the site landing page
  includes it as a snippet so PyPI/GitHub visitors lose nothing and
  content exists once.
- 2026-07-14: decisions.md is published — the repo is public and the
  reasoning is part of the library's documentation surface.
- 2026-07-14: Slice 1 finding: `:class:`/`:meth:`/`:attr:` reST roles
  render as literal text under mkdocstrings (strict build passes; output
  is wrong). Decision: replace roles with plain backtick code spans in
  docstrings — reads cleanly in IDE hovers, `help()`, and the site alike;
  auto-linking is given up deliberately (small API, short nav).

## Deferred

- PyPI publish workflow on the same tags.
- Docs versioning policy past 1.0 (how many versions to keep listed).

## Done criteria

- `uv run --group docs mkdocs build --strict` exits clean locally and in CI.
- Site nav shows: Home, Usage, API reference, Architecture decisions.
- API pages render attribute docstrings for models and full docstrings
  for the client, with working cross-references.
- A `v*` tag push runs the deploy workflow green and the published site
  offers the version in its selector (verifiable at first release tag).
