# LLM-facing documentation

## Goal

An agent or LLM asked to write code against libcivicclerk currently has to
fetch five separate doc pages, and the API reference page is nothing but
mkdocstrings directives — so a model that reads the markdown source learns
no method signatures at all. Worse, nothing in the docs says what the
library *lacks*, so a model will confidently reach for an async client, a
search method, or an auth parameter that does not exist. This work gives
LLM consumers a single fetchable artifact containing the whole
documentation set, and adds the one page of content those consumers need
that humans never asked for.

## Requirements

- The built site serves `llms.txt`: an index in the conventional shape
  (H1, blockquote summary, H2 sections of annotated links).
- The built site serves `llms-full.txt`: the whole documentation set as one
  flat markdown file, with the API reference rendered as real signatures
  and docstrings — not `:::` directives.
- A "Cheat sheet" page appears in the site nav and covers, compactly:
  the complete public surface (every `__all__` export and every client
  method), the two traps a model will otherwise violate (naive wall-clock
  datetimes; the two non-interchangeable id namespaces where a wrong call
  can silently fetch the wrong document), and a negative-space list of
  what the library deliberately does not provide.
- README and docs home link the two generated files so a human can hand
  the URL to an agent.

## Out of scope

- No library code or docstring changes.
- No root-level `llms.txt` outside mike's version directories; the files
  ship inside each versioned build (see Decision log).
- No per-page `.md` mirrors (the Mintlify-style `page.md` convention).
- No new CI jobs; the existing strict docs build is the gate.
- No changes to what the human-facing pages already say — the cheat sheet
  restates, it does not relocate.

## Constraints

- Docs tooling stays in the `docs` dependency group; runtime deps stay
  httpx-only.
- `mkdocs-llmstxt` renders from the built HTML, so it must run after
  mkdocstrings; verify the API reference actually arrives as signatures in
  `llms-full.txt` rather than directive text — that check is the tracer's
  whole point, and if the plugin cannot deliver it the approach is wrong.
- The strict build (`uv run --group docs mkdocs build --strict`) must stay
  clean; it already runs in CI.
- Public-repo constraint applies: no municipality references, fictional
  tenants only.
- The cheat sheet's surface listing is duplicated information by nature —
  it will rot if the public API changes. Keep it to names and one-line
  purposes so the drift is cheap and visible, and let `api.md` remain the
  authority on signatures.
- The generated files live at `…/libcivicclerk/latest/llms.txt`, not the
  domain root. Links must use that path.

## Environment

- `uv sync --group docs` — install docs tooling.
- `uv run --group docs mkdocs build --strict` — the build gate.
- `uv run --group docs mkdocs serve` — local preview.
- `prek run --all-files` — full hook suite.

## Decision log

- **Generated, not hand-written.** A hand-maintained `llms-full.txt` would
  be a second copy of the docs, guaranteed to drift. The plugin regenerates
  it on every build.
- **Files ship inside the versioned build, not at the domain root.** The
  convention puts `llms.txt` at the site root, but mike owns the gh-pages
  root and keeps only a redirect stub there. Copying a file into that root
  from CI would mean machinery mike does not manage, plus a root file free
  to drift from the versions beneath it. Accepting `/latest/llms.txt` keeps
  each artifact pinned to the version it documents; the cost is that a bare
  root URL 404s, which we absorb by linking the real path prominently.
- **The cheat sheet is a human page.** An LLM-only page is a page nobody
  proofreads; making it part of the nav means it earns review and serves
  anyone returning to the library after a break.

## Deferred

- A root-level `llms.txt` redirect, if agents in practice guess the root
  URL and give up on the 404.
- Slice 1 finding: the HTML→markdown conversion does not escape `|` inside
  table cells, so a union-typed parameter (`http_client: Client | None`)
  splits across columns in `llms-full.txt`. No information is lost, only
  misaligned. A `preprocess` script could escape it; not worth the
  machinery until it demonstrably confuses a reader.
- Per-page markdown mirrors, if a consumer asks for them.

## Done criteria

- `uv run --group docs mkdocs build --strict` exits clean and emits both
  `llms.txt` and `llms-full.txt` into the built site.
- `llms-full.txt` contains the client's method signatures and docstrings as
  text — grep for a method name and find its signature, not a `:::` line.
- Site nav shows: Home, Usage guide, Command line, Cheat sheet, API
  reference, Architecture decisions.
- The cheat sheet lists every name in `libcivicclerk.__all__` and every
  public client method.
- README and docs home carry working links to both generated files.
